# 协议兼容性

本文来自**真实二进制实测**（frpc 0.71.1 → frps 0.71.1，ImmortalWrt/OpenWrt x86），每项都验证了「登录成功 + 状态接口正常 + 真实数据回环」。

## 实测矩阵

| 能力 | 结果 | 服务端要求 |
| --- | --- | --- |
| tcp 传输（TLS 开/关） | ✓ | 无 |
| websocket 传输 | ✓ | 无 |
| kcp 传输 | ✓ | `kcp_bind_port` **等于**客户端 `serverPort` |
| quic 传输 | ✓ | `quic_bind_port` **等于**客户端 `serverPort` |
| stcp 代理 + visitor | ✓ | 无 |
| sudp 代理 + visitor | ✓ | 无（visitor 模式，**不占服务端 UDP 端口**） |
| xtcp 代理 | ✓ | 无（P2P 视网络环境而定，失败会回落到中转） |
| http 代理 | ✓ | `vhost_http_port`；子域名路由需 `subdomain_host` |
| https 代理 | ✓ | `vhost_https_port`；**本地服务必须自己说 HTTPS**（TLS 透传） |
| tcpmux 代理 | ✓ | `tcpmux_httpconnect_port` |
| wss 传输 | ✗ | frps 自身 TLS 下不可用，需前置 nginx/CDN 终止 TLS |

## 最重要的一个结论：kcp / quic 的端口必须对齐

frpc 的 `protocol = "kcp"` 或 `"quic"` **不会**把 `serverPort` 改写成服务端的 kcp/quic 端口，它始终连接 `serverAddr:serverPort`。

因此：

- 想用 kcp：服务端 `kcpBindPort` 必须 **等于** 客户端 `serverPort`（常见做法：都设 7000，TCP 与 UDP 同端口号不冲突）
- 想用 quic：服务端 `quicBindPort` 必须 **等于** 客户端 `serverPort`（例如服务端开 7003，客户端填 7003）
- 同一台 frps 上 kcp 与 quic 不能同时占用同一 UDP 端口，所以常见的组合是：`kcpBindPort = 7000`（默认端口）+ `quicBindPort = 7003`（客户端按需填 7003）

## 服务端配置示例（覆盖全部实测协议）

`frps.toml`：

```toml
bindPort = 7000
auth.method = "token"
auth.token = "your-token"

# kcp：与 bindPort 相同最省心
kcpBindPort = 7000
# quic：客户端 serverPort 需填 7003
quicBindPort = 7003

# http / https / tcpmux 代理
vhostHTTPPort = 7004
vhostHTTPSPort = 7005
tcpmuxHTTPConnectPort = 7006

# 状态面板（与 App 的「状态监控」无关，仅浏览器访问用）
webServer.addr = "0.0.0.0"
webServer.port = 7500
webServer.user = "admin"
webServer.password = "change-me"
```

## wss 为什么不行

wss（TLS + WebSocket）在 frps 侧的处理路径是：TLS 解包 → yamux → frp 协议，而 wss 客户端在 TLS 之后发送的是 WebSocket 升级请求，两者不匹配。

真实世界的 wss 用法是：**frps 前面放一层自己持有证书的反向代理**（nginx / Caddy / CDN），由它终止 TLS 并把 WebSocket 转发到 frps 的 `bindPort`，frps 直接看到明文 `GET /~!frp` 升级请求。所以：

- 手机直连 frps 时请用 `websocket` 或 `tcp + TLS`
- 需要过 CDN / 严格网络环境时再考虑 wss，并在服务端前置反代

## 老版本 frps 的差异

| frps 版本 | 差异 |
| --- | --- |
| < 0.53 | 无 QUIC；无 wss 相关支持 |
| 0.51.x | 无 `bind_udp_port`（sudp 走 visitor，不受影响）；无 h2/v2 协议 |
| 0.50+ | TCP 传输默认开启 TLS（本 App 默认也是开，老服务端需手动关闭 TLS） |

## 如何自行验证

```bash
# 1. 生成配置（App 的「导出」即可得到同样的 toml）
# 2. 用官方 frpc 跑一遍
frpc -c frpc.toml
# 3. 看日志：login to server success / start proxy success
# 4. 用真实数据打一次：curl 访问远端端口 / 用 visitor 本地端口
```

App 内对应位置：日志页可看到同样的 frpc 输出，主页「代理规则」会显示状态与实际端口。
